# Decision: Synchronize current provider guidance with CLI 0.5.6

Status: proposed

## Problem

The next CLI patch preserves named-command JSON diagnostics. Provider installation guidance and the current OpenSandbox gate still select the independently verified CLI 0.5.5 inputs; a later CLI release must not inherit that evidence without a rerun.

## Decision

After normal CLI merge and formal 0.5.6 publication, recommend that patch in current bilingual acceptance guidance and the catalog Skill. Select the actual reviewed, normally merged immutable CLI SHA in the existing OpenSandbox workflow and run its complete current consumer gate. Preserve the earlier .5 receipt and all existing assertions.

## API Design

N/A — no provider runtime, capability, package version, compatibility alias or host API change. The SDK remains public 0.4.0a6; template source remains merged 389302f5dc9429a4b215801dbd4025d4dba95f7e; Node runtime source remains 63d7cd8ece221b9f968eef51eeb932ea334c90d3.

## Alternatives considered

Reusing the .5 pass as .6 evidence or guessing an unreleased merge SHA would be inaccurate. A new acceptance runner or plugin version is unnecessary; reuse the existing complete default/portable/proxy gate.
